### C2. How `immediate_disclosure` is built (`156_rebuild_s6_assembly.py`)

```
109 ev['reported_dt'] = pd.to_datetime(ev['reported_date'], errors='coerce')
110 ev['disclosure_delay_days'] = (ev['reported_dt'] - ev['bdt']).dt.days
115 inv = ev['disclosure_delay_days'] < -30          # wrong-field record
121     ev.loc[inv, 'disclosure_delay_days'] = np.nan
125 neg = ev['disclosure_delay_days'] < 0            # -30..-1: field-level imprecision
131     ev.loc[neg, 'disclosure_delay_days'] = 0
135 ev['immediate_disclosure'] = (ev['disclosure_delay_days'] <= 7).astype(float)
136 ev.loc[ev['disclosure_delay_days'].isna(), 'immediate_disclosure'] = np.nan
```

- **Dates:** PRC `reported_date` (notification) minus PRC `breach_date` (occurrence).
- **Units:** **calendar days** (`.dt.days`); threshold ≤ 7 calendar days.
- **Missing dates:**
  - An unparseable `reported_date` gives a NaN delay and a NaN flag.
  - A delay below −30 becomes NaN, with `delay_invalid = 1`.
  - A delay from −30 to −1 is **recoded to 0** (`delay_recoded = 1`) and therefore counts as immediate.
- The clock is occurrence-to-public-notification. It is not 47 CFR 64.2011's seven-business-day law-enforcement clock (`164:61-110` quotes the rule).
